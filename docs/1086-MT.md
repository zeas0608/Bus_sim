# 1086号車でAT・完全MT・自動クラッチMTを運転する

高松210あ1086の車両設定は6速AT。ゲームでは同じ車体・車輪・運転席のまま、架空のMT改造車として練習できる。起動時は毎回 **AT (1086) / N / Park ON**。ベース版のAT走行と操作はユーザーがWindowsのUE5.5.4とF310で確認済み。今回の変更後のUEビルド、AT回帰、MT実走、音の聴感、性能は実機確認待ち。

## Windowsで更新する

1. UEを **Save All** して終了する。GitHub Desktopで `feature/1086-mt-driving` を選び **Fetch origin / Pull origin**。UE5.5.4、Visual Studio 2022、F310のXInput設定は従来どおり。
2. エクスプローラーで **scripts → UPGRADE_KOTODEN1086.cmd** をダブルクリックする。プロジェクトと同じ親フォルダーの `Recovery_Backup/Kotoden1086-日時-ID` にContent・Configをコピーした後、Development Editor / Win64をビルドする。標準外のエンジン配置の場合のみ、PowerShellで `.\scripts\setup_kotoden1086.ps1 -Upgrade -UnrealRoot 'D:\Epic\UE_5.5'` のように指定する。
3. 通常起動した **L_1086_Drive** で **Play**。初回はシェーダー準備を待つ。既存の完全なBuildフォルダーがあれば新しい順でそのマップを開く。既存の車体とPhysics Assetだけがある場合は、新規Buildフォルダーに走行用Blueprintとマップを生成する。使用できるローカル車体がない場合は同梱FBXから新規作成する。生成が必要な場合だけ、準備専用エディターが起動・終了し、成功レポートと生成ファイルを確認してから通常のエディターを起動する。
4. 途中で止まったら `Saved/Setup1086` の最新のBuildEditor／SetupFailureログ、またはUpgradeResult.jsonを確認する。**scripts → CHECK_1086_ERROR.cmd** は診断レポートをまとめる。既存インストールに更新を適用する際は **UPGRADE** を使う。従来の **START** は既存マップがあるとビルドを省く。

## 操作

| 操作 | 入力と挙動 |
| --- | --- |
| モード | 停車＋Park ONで **T**。AT → Manual MT (fictional) → Auto-clutch MT (fictional) → AT。切替後はN。MTのエンジンはOffから始まる |
| MTの始動・停止・再始動 | 停車、Park ON、Nで **I**。StartingからRunningを待つ。エンスト後も同じ手順 |
| シフト | **RB** が1段上げ、**LB** が1段下げ。順は R・N・1〜6。完全MTで段に入れるときはLTを85%以上踏む。NへはLTなしでも抜ける。前進中のR、逆行中の前進段、過回転になる段、同時押しはHUDに拒否理由が出る |
| MT発進 | Aで停車保持 → **T → I** → Running → **LTを踏み切りRBで1速** → SpaceでPark解除。Aを離し、RTを少し入れながらLTを徐々に戻す。変速時はRTを戻し、LTを踏み、RB、LTを戻す |
| 自動クラッチMT | 停車・Park ONでモードを選び、Iで始動。RBで1速、Park解除、RTで発進。発進・変速・低回転時の係合を自動制御する。段の選択は毎回運転者が行う |
| AT | 従来どおり **1 / 2 / 3** でD / N / R。MT中はこの3キーを無効化し、セレクターのそばに訓練用の段表示を出す |
| 共通 | RTアクセル、左スティック操舵、A常用ブレーキ、Space駐車、F / M前扉・中扉、L前照灯、Q / E指示器、C視点、右スティックで運転席の見回し。既存のマウススイッチも使用可能 |
| 記録と勾配 | **K** でCSV開始／終了。記録中はHUDにREC。平坦な試走場で停車・Park ONの状態で **G** を押すと、前方約10 mに長さ40 m・勾配5%の試験用スロープを1つ配置する。プレイ終了で消える。上端の手前で停車する |

## 実車と技術上の近似

- MTは独立した回転慣性・アイドル調速・回転制限・トルク曲線・回転抵抗を持つ。後輪角速度の平均×符号付きギア比×最終減速比が入力軸回転数になる。滑り速度に比例する摩擦トルクを係合率の二乗に応じた容量で制限し、エンジンには反力、後輪には減速比と効率を通じたトルクを等分する。LT全踏み／Nでは駆動ゼロ。車輪からエンジンを回す領域ではエンジンブレーキが出る。失速後は駆動を切る。
- MT積分は120 Hz。ゲームスレッドが直近のChaos出力をサンプルし、計算した指令を次の物理更新へ渡す。物理スレッドと各サブステップを同期した測定ではない。250 msを超えるフレームや異常値は駆動指令ゼロとし、Faultを記録する。摩擦は滑り速度を使った近似で、熱、クラッチ板の弾性、実車トルコン特性は対象外。
- 同じPawnのまま標準ATをN・スロットル0にし、MT時だけ4輪を `SetTorqueCombineMethod(Override)` にする。前輪は駆動0、後輪は各半分。常用ブレーキは4輪、駐車ブレーキは後輪に外部トルクを指令する。標準と外部の加算は行わない。ATへ戻る時、降車時、破棄時に外部指令をクリアし、標準の方式に戻す。車体の再生成や走行中の `bMechanicalSimEnabled` 切替は行わない。
- UEの接続箇所は `ChaosVehicleWheel.h` の `GetWheelAngularVelocity`（rad/s）、`ChaosWheeledVehicleMovementComponent.h` の `GetWheelState`、`SetDriveTorque`、`SetBrakeTorque`（N·m）、`SetTorqueCombineMethod`。Overrideで駆動・制動の双方が置き換わることは先行P0のユーザー確認に基づく。表示・音・CSVにはMT時は独自エンジン、AT時はChaosのRPMと実際の段を使う。
- MTの仮値は [DefaultGame.ini](../Config/DefaultGame.ini) にある。1〜6速は5.20 / 3.15 / 2.05 / 1.45 / 1.00 / 0.76、Rの絶対値5.10、最終比5.00。慣性2.4 kg·m²、最大650 N·m、クラッチ容量980 N·m、滑り係数18 N·m/(rad/s)、アイドル650・制限2800 rpm。6段の各比を変更できる。数値は訓練用。
- 音は独自の24 kHzモノラル合成。RPMに伴う燃焼周期、負荷とRTによる倍音、速度に伴う路面音、制動、シフト時の打音、扉作動中の空気音を混ぜる。運転席／車外でレベルを切り替える。実車録音は使用していない。
- 現在の車体を使う場合も乗降口の照明、ドアの立上がり・停止、MT運転台表示が適用される。新しいBlender/FBXにはメーター目盛・ボタン縁取り、降車ボタン筐体、灯具のプリズムと反射器も収録した。筐体は造形のみ。写真未照合の配置は推定。既存SKの造形は保持される。新版の造形もUEで比較したい場合は **Tools → Execute Python Script → scripts/import_kotoden1086.py** を1回実行すると別のBuildフォルダーにモデル一式を作れる。

## 記録・実走テスト

CSVは `Saved/BusTelemetry` に走行ごとの新規ファイルを作る。約20 Hzで実際に観測した時刻を秒で記録する。低fps時は欠測を複製しない。時刻、ゲームフレーム時間、モード、状態、RPM、ギア、符号付き速度(m/s)、LT、係合率、滑り(rpm)、RT、ブレーキ、操舵、Park、ドア、灯火、カメラ、車体Yawを収録する。FL/FR/RL/RRの駆動・制動は指令値とChaos読み取り値（N·m）を区別する。ATで外部指令が存在しない欄、未取得の車輪結果は空欄。NaN/Infは空欄とFaultで示す。Kを再度押すかPIEを終了すると残りをフラッシュする。

| 確認 | 操作と合格の目安 |
| --- | --- |
| AT回帰 | 最初のNからKを開始。D・Park解除、RTで前進、左スティックで旋回、Aで停止。Space、前／中扉を全開→全閉、灯火と左右指示器、Cで車内外を切替。MTからATへ戻った後も同じ操作で走れること |
| 完全切断・半クラッチ | 完全MTの1速でLT全踏み＋RT。停止中は駆動指令0、RPMが上がる。LTをゆっくり離すと滑りと後輪指令が変わり発進。走行中にLTを踏むと惰行する |
| エンスト・再始動・エンジンブレーキ | 低速・低RTでLTを急に戻し失速を確認。停車、Park ON、N、Iで再始動。走行中にRTを離し、同じ速度域でクラッチ接続時と切断時のトルク符号・減速度を比較 |
| Rと自動クラッチ | 停車してNからLBでR、LTを戻して後退。前進中はR投入拒否。自動クラッチMTでLTを使わずRBで1速発進、RBで2速。シフトしない限り段が変わらないこと |
| 坂道 | Gで用意したスロープの途中でAを保持して停車。1速でRTと半クラッチを合わせ、Aを徐々に解放して登坂。右／左の車輪指令と速度をCSVで比較 |
| 視聴・性能 | 針とHUD/CSVのRPM・速度を比較。エンストで燃焼音が消えること、扉音・乗降口照明、制動音、カメラを確認。1280×720でコンソールの `stat fps` / `stat unit` とCSVのframe_msを記録。60fpsは目標 |

ATの記録は付属Pythonでも確認できる。直進・旋回・停車・扉一往復・灯火・左右指示器・視点をひとつの記録に含めてから、以下をリポジトリ直下で実行する。`NO EVIDENCE` は操作または計測が不足している項目。画面での確認も併用する。

```powershell
$trip = Get-ChildItem Saved/BusTelemetry/*.csv | Sort-Object LastWriteTime -Descending | Select-Object -First 1
& 'C:\Program Files\Epic Games\UE_5.5\Engine\Binaries\ThirdParty\Python3\Win64\python.exe' Tests/check_1086_trip.py $trip.FullName
```

## クラウドで行った検査

- C++17で本番のMT計算を直接コンパイルし、N・LT1のゼロ、半クラッチ、エンスト・再始動、ボタン長押し、R符号、過回転拒否、自動クラッチ、エンジンブレーキ、5%勾配の簡易車体、30/60fps、異常入力、駐車・扉・入力異常の組合せを試験。合成音は無音状態、回転数別の基本周波数、制動・扉の出力を検査。
- PowerShell 7で本番更新スクリプトを隔離フォルダーの模擬ビルド・エディターで実行。既存Buildを選ぶケース、新規生成、生成失敗を検査し、既存資産・バックアップのハッシュを比較。Pythonで既存SK再利用と初回取り込みの分岐、AT記録判定の成功／不足も検査。
- Blender 4.3.2でモデル再生成・FBX再読込・試験ポーズ・三視点のレンダリングを実行。原本939部品、FBX23メッシュ、いずれも23骨・43材質・141,718三角形。UE5.5.4のWindowsビルド、実インポート、F310を接続した今回の試走、実録CSV、720p性能は未検証。
