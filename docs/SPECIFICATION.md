## 1. 目的と基本コンセプト

日本の路線バスの運転と運行を体験できるPC向け3Dシミュレーター。最終的な舞台は香川県高松市に実在する道路・建物をできるだけ忠実に再現した、ことでんバス「御厩線」高松駅発の路線。単なるドライブゲームではなく路線バスの運行業務も視野に入れる。

**優先順位**: (1) 操縦・車両物理の再現度、(2) 運転席3Dモデルの精度・操作性、(3) 実在車両の形状・音、(4) 実在道路・建物・運行業務、(5) 描画演出・画質。画質よりモデル形状・機器配置と物理挙動を重視する。

完成版は個人用で、販売・一般配布を前提としない。費用は原則ゼロ（既存PC・利用可能なCodex枠を前提）。無料素材と公開データの利用条件を守る。

## 2. 開発環境／ハードウェア

| 項目 | 要求・設定 |
|---|---|
| OS | Windows PC（ユーザー環境） |
| CPU | Intel Core i5-12400 |
| GPU | NVIDIA GeForce RTX 3060（VRAM容量は別途確認） |
| メモリ | 16 GB |
| ゲームエンジン | Unreal Engine 5。初期候補 5.5.4（PLATEAU SDK v3.2.2との互換性を優先した暫定値） |
| 言語 | C++（車両物理・入力・ログ）＋Blueprint（UI・演出・シーン構成） |
| 制作補助 | Codex、Blender、Visual Studio Community、必要に応じてPython・無償ツール |
| 解像度 | 1280×720（720p）許容 |
| 目標FPS | 60 fps。ただし実測するまでは性能を保証しない |
| 入力機器 | Logicool F310（背面スイッチX側／XInput）＋マウス＋キーボード |

**性能方針**: レイトレーシングは初期オフ、影・後処理・描画距離は調整可能。精密モデルは残しつつLOD、テクスチャ最適化、エリアストリーミングを使う。PCのメモリ16 GBで編集・起動可能な設計を優先。

## 3. 開発対象の優先順位

### 3.1 最初の完成版（Ver.0.1: 走行テスト版）

- 実在地図ではなく、直線、曲線、坂道、交差点を備えた自作テストコースを使う。
- 仮バス車両（箱型でも可）で、走行、旋回、停止、ギア切替、クラッチ操作を試す。
- Chaos Vehiclesを車体・車輪の土台として採用する方向を**先に検証**する。
- 完全MTとクラッチ自動MTを切り替えられるようにする。
- 入力・車両状態・ログ・簡易HUDを使って物理挙動を検証する。
- 故障・整備・本格的な乗客・運賃・ダイヤ機能はこの段階では実装しない。

### 3.2 その後の優先順位

1. 実車の写真・寸法・仕様資料が最も多い**現代のことでんバス車両**を選定（型式・車番は現時点で未確定）。
2. 運転席を優先して高品質な車両モデルを制作。既存の利用許諾可能な無料モデルを活用し、不足部分をBlenderで自作。
3. 主要スイッチ、計器、ミラー、車外カメラ、音響などを再現。
4. 高松駅発・県立総合プール方面の御厩線について公式の停留所順・時刻表を検証し、実在道路・建物を作る。
5. 乗客、停留所、ドア、車内放送、ダイヤ、運賃、行先表示などの路線運行システムを追加。

## 4. F310入力仕様（確定要求と実装案）

### 4.1 基本操作

| 操作 | 入力 | 備考 |
|---|---|---|
| ステアリング | 左スティック左右 | アナログ。感度・デッドゾーン・セルフセンタリングは調整可能 |
| アクセル | RT | アナログ0〜1。押し込み量でスロットル変更 |
| クラッチ | LT | アナログ0〜1。**0=ペダルから足を離す（クラッチ接続）、1=踏み切る（切断）** |
| サービスブレーキ | Aボタン（暫定） | 押す間、制動指令/ブレーキ圧が滑らかに上昇。離すと滑らかに低下 |
| シーケンシャル変速 | RBでアップ / LBでダウン（暫定） | 最初の走行版に実装 |
| Hパターン変速 | 右スティックまたは画面内レバーをマウス操作 | 段数・ゲート・モード切替方法は車両確定時に調整 |
| 視点移動 | 通常時は右スティック | Hパターン操作モードと排他。マウス視点操作も提供 |
| その他 | キーボード・マウス | 始動、駐車ブレーキ、ライトなど |

**明示的な競合**: 右スティックを「視点」と「Hパターン」の同時操作には使えない。操作モードを示すHUDと明確なモード切替を設け、Hパターン中は視点移動を止める。切替の具体ボタンは未確定なので、設定可能にして試作中に確認する。

### 4.2 MT／クラッチ

- 「完全MT」ではLTによるクラッチの踏み込みを物理計算へ反映し、半クラッチ、空ぶかし、ギア比に応じたトルク伝達、エンスト、坂道発進を実装する。
- 「クラッチ自動MT」ではギア操作は手動、クラッチ接続・切断の操作をゲームが補助。簡単なATへ勝手に変更しない。
- シーケンシャル／Hパターンは**入力方式**の違い。車両の変速機の物理モデルは共通化する。
- ニュートラルとリバースを扱う。逆方向への走行中の無理な変速は安全に拒否し、理由をHUDへ表示する。
- ギア数、個別ギア比、ファイナル、アイドルRPM、最大RPMは**車両の資料を確認後に確定**。テスト版では暫定値を設定データに明記し、実車値と誤認させない。

### 4.3 ボタン式ブレーキ

- ボタンは二値入力だが、**制動指令は0〜1の連続値**とする。
- 押下中に `BrakeCommand` を一定の増加率で最大1へ近づけ、離すと別の減少率で0へ戻す。上昇率・下降率はData Asset等から変更可能。
- 初期版では常用時のブレーキ特性のみ。空気圧異常・故障シナリオは実装しない。
- 駐車ブレーキはサービスブレーキと独立した操作・状態を持つ。
- **開発メモ**: 実車の空気ブレーキの挙動と違う部分があるため、精度向上時に踏み直し/開放特性を検証する。

## 5. 車両物理の実装方針

### 5.1 アーキテクチャ

- Chaos Vehicles (ChaosWheeledVehicleMovementComponent等) を車輪・タイヤ・サスペンション・車体挙動の土台として評価する。
- 独自C++モジュールでエンジン慣性、回転数、アイドル制御、トルク曲線、クラッチ容量／滑り、ギア比、エンジンブレーキを計算する。
- エンジン計算結果からタイヤの接地駆動力へ渡す**結合経路の実現可能性を先に実験**する。標準Chaos側と独自側で駆動トルク・ギア比が二重適用されないようにする。
- もし通常のChaos Vehiclesを無改造のまま使えないなら、拡張ポイント／Chaos Modular Vehicles／最小限のエンジン拡張を比較し、実証結果を記録してから選ぶ。最終実装を未検証のまま確約しない。

### 5.2 物理的に扱うもの

- 車両質量、重心位置、ホイールベース、輪距、舵角、タイヤグリップ、転がり抵抗
- 駆動トルクと車輪回転、エンジン負荷、クラッチスリップ、ギア変速
- 前後・左右の荷重移動、加減速時のピッチ、旋回時のロール、サスペンション
- 勾配、エンジンブレーキ、常用・駐車ブレーキ、低速時の挙動
- 数値シミュレーションは可能な限り一定時間刻み・サブステップを使用し、フレームレートによる挙動変化を抑える

### 5.3 仕様値と調整

- 物理定数・入力応答はC++へ直書きしない。原則 `Data Asset` / `Curve` / 設定データから調整可能にする。
- 全パラメータに単位（kg, m, rad, Nm, rpm, Pa, s 等）と出典/暫定を記録する。
- 実車データ未取得時は「仮パラメータ」。検証結果が出るまで「実車と同一」と断定しない。
- 故障・機械異常・温度による性能劣化などは対象外（運転時の正常な挙動を優先）。

## 6. 3D車両・運転席・カメラ

- 運転席を外観より先に高精度化する。運転者から見えるメーター・ハンドル・スイッチ・ミラー・操作レバーの位置関係にこだわる。
- 主要スイッチはマウスでクリックして操作できる。その他の機器は将来拡張。
- メーターはゲーム内の実際の車速・回転数・ブレーキ状態と連動する。
- 運転席視点、座席の前後・上下調整、左右確認、ミラー、車外視点、自由カメラを実装する。初期テスト版では運転席・追従カメラを優先。
- 利用できる無料3Dモデルの権利を記録し、必要に応じてBlenderで修正。モデルや商標が未確定の間は仮名称／仮素材を使う。
- 高画質化より、可動部と寸法・見た目の精度を優先する。

## 7. 音響

- 原則として合成音を中心に設計。回転数・負荷・ギア・速度に連動するエンジン音、加減速音、変速音、ブレーキ音を生成／加工する。
- 車体の振動・ロードノイズ・風切り音もパラメータに応じて合成する。
- 簡易プロトタイプ音から開始し、MetaSounds等の使用可能な手段で精度向上する。
- 録音素材を使用する場合は許諾・ライセンスを確認し、無断転載しない。

## 8. 初期テストコース

- 直線（発進・加速・制動テスト）、複数半径の曲線（舵角・内輪差）、勾配（発進・登坂・エンジンブレーキ）、交差点（低速・一時停止）を用意。
- 検証区間ごとに開始位置を切り替え可能にする。
- 最初は交通AI・歩行者・信号制御・建物を必須としない。

## 9. ログ・デバッグ・チューニング

- HUD/デバッグ画面: 車速、エンジンRPM、ギア、クラッチ入力・スリップ、スロットル、ブレーキ指令、車輪回転・駆動力、FPS。
- ログをCSV等で保存できる。主な列: タイムスタンプ、速度[m/s]、エンジン回転[rpm]、ギア、アクセル、クラッチ、ブレーキ、駆動トルク[Nm]、旋回角など。
- ログから速度推移・RPM・入力・ブレーキのグラフを確認できるようにする。
- 設定画面で物理定数・入力デッドゾーン・ブレーキ増減速度を変更可能にする。
- 開発中の診断情報と通常プレイ時のHUDは分離する。

## 10. 将来: 高松市・御厩線・路線運行

- 高松市は現実の道路・交差点・バス停位置・主要建物をできるだけ忠実に再現する。
- 地理素材: PLATEAU、OpenStreetMap、必要なオープンデータ。法的な利用条件とデータ品質を確認。
- 御厩線は「高松駅→県立総合プール」方面から着手。**最新の公式停留所一覧・ダイヤ・経路**を実装時に必ず再確認する。Googleマップは参照用とし、利用規約に反する地図データ抽出は行わない。
- 乗客の乗降、ドア、車内放送、運賃、時刻表、遅延、行先表示、交通AIは将来フェーズ。初期版には含めない。
- 外部アセットにライセンス情報・取得元URL・改変履歴を付ける。

## 11. Ver.0.1 完了条件（合否判定）

1. UE5プロジェクトがローカルでコンパイル・起動し、テストコースに入れる。
2. F310 (XInput) のRT/LTが独立した0〜1のアナログ値として取得でき、画面上に数値を表示できる。
3. ステアリングと車両姿勢が操作に連動し、直線・曲線・坂道で走行できる。
4. 完全MTで半クラッチ・ニュートラル・エンスト・ギア切替の挙動が確認できる。
5. クラッチ自動MTへの切替が可能で、ギア操作は手動のまま動作する。
6. Aボタンの押下時間に応じてブレーキ指令が増加し、離すと低下する。ログ上も連続値である。
7. エンジンと車輪へのトルク伝達の経路が説明でき、Chaos側との二重計算がないことを検証する。
8. 速度・RPM・ギア・クラッチ・ブレーキ・FPSを表示し、再現可能なCSVログを記録できる。
9. 720pでFPSを**実測して記録**する。60fpsは目標であり、未達でも未達と明記して改善課題を切る。
10. 説明書に起動手順・既知の問題・未実装・テスト結果が記載されている。

## 12. 禁止・制約

- 未検証機能を「実装・動作済み」と記載しない。
- 実車の仕様値・ルート・車番・公式データを推測で事実扱いしない。
- 実車のロゴや車両・音声の素材を権利確認なしに取得・再配布しない。
- 正式な許可なしにGoogleマップの地図・3D形状を抽出して組み込まない。
- 本人の承認なしに有料アセット・有料サービスを導入しない。
- 既に決定したMTの仕様を簡素化したAT専用版へ無断で変更しない。
