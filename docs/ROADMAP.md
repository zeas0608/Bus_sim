# 開発ロードマップ — ことでんバス 3D運転シミュレーター

- 文書版: 1.1
- 原則: 1タスク＝小さな変更、検証記録付き、動作する状態を維持
- **現在の開発優先順位（2026-11-23確定）:** 高松市の道路・御厩線マップ → 1086号車の車体・外装・内装 → 運転席 → 走行物理・運転感覚 → サウンド
- 原則: すでに動くAT／完全MT／自動クラッチMTの動作を維持しながら、この順で品質を上げる。

1086号車の基本操作はユーザーがWindowsで概ね動作確認済み。次は **P5 高松市マップを先行着手**し、高松駅周辺の道路・停留所・交差点から段階的に拡張する。地図と道路の実測・公式情報を照合し、推定形状・未確認情報を明示する。既存の車両・Blueprint・ローカルBuildフォルダーは消さない。AT回帰・MT走行・性能の正式判定は [試走手順](1086-MT.md) に沿って追って記録する。

## 次に着手する順番（旧P0〜P6の番号は開発フェーズ識別子であり、実施順序ではない）

1. **P5 高松の道路・路線制作** — 御厩線の高松駅側から段階的に3D化。まず道路幅・交差点・走行可能な路面・バス停・信号・主要ランドマーク。実在のルート／停留所を公式情報で照合し、地図データ出典・ライセンスを保存。車両が実際に走れるミニ区間を先に完成。
2. **P4 車体・外装・内装の精密化** — 寸法、形状、窓・灯具、座席、床、扉、マテリアルを実車資料と照合。
3. **P3 運転席の精密化** — 計器、スイッチ、ハンドル、ミラー、操作性・視点。
4. **P2 走行物理・運転感覚の調整** — 乗り心地、制動、操舵、AT/MTクラッチ・エンジン挙動。
5. **P3 サウンドの改善** — エンジン・変速・ブレーキ・ドア・ウインカー・車内外環境音。

P6（乗客・運賃・ダイヤ等の運行業務）は、この5項目の後に本格化する。P5の初期区間では走行に必要な停留所・道路設備のみ先行する。


## 開発の入口（技術スパイク）

**P0: UE5とF310／Chaosの実現可能性を確かめる。** 先に完成を約束しない。

1. UE5.5.4、Visual Studio 2022、Windows SDK、Chaos Vehiclesが利用可能か確認。
2. C++の空プロジェクトを作り、ビルド・起動を確認。
3. F310 (XInput) のRT/LT、左右スティック、A/LB/RBの値を可視化する。
4. 仮の車両でChaos Wheelsを動かし、ブレーキ・操舵を試す。
5. 独自のクラッチ計算→車輪トルクの渡し方を**最小構成**で調査・試験。標準エンジン/トランスミッションと駆動トルクが二重にかからない設計を確認。
6. できない場合は理由と代替案（Chaos Modular Vehicles、拡張コンポーネント等）を技術メモとして残し、無断で設計変更しない。

**P0完了条件:** プロジェクトが起動し、F310入力が表示され、少なくとも1つの実行可能なMTトルク結合案をコードまたは実験結果として示せる。実機未検証の場合は未完了として記録。

## P1: 走行できる最小プロトタイプ

- 直線・曲線・坂道・交差点の簡易テストコース。
- 仮のバス、ステアリング、RTアクセル、Aブレーキ、駐車ブレーキ。
- 追従カメラ／運転席カメラ、速度計、基本ログ。
- 初期シミュレーション定数は仮値であることを明示。

**完了条件:** ユーザーがF310で発進・曲がる・停止でき、ログが保存できる。

## P2: MTと車両物理

- 独自エンジンRPM/トルク/慣性モデル。
- LTアナログクラッチ、半クラッチ、スリップ、エンスト、始動。
- 手動変速（LB/RB）、ニュートラル、リバース、クラッチ自動モード。
- ボタンブレーキの圧力増減、車体荷重、勾配、グリップ、サスペンションの調整。
- 加速・制動・旋回ログを記録し、チューニング画面を作る。

**完了条件:** `SPECIFICATION.md` のVer.0.1テスト基準を満たす。未達は計測値と理由を残す。

## P3: 運転席・操作・音響

- 精密な運転席モデル（未確定車種の仮モデルから移行）。
- 主要スイッチのマウス操作、メーター、座席調整、ミラー、車外/自由視点。
- 右スティックHパターン／マウスHパターン、視点モード競合の解消。
- RPM・トルク・速度に連動する合成エンジン音、変速、振動、路面、風切り音。
- Realistic/Quickエンジン始動の切替。

**完了条件:** 運転席視点から操作でき、入力の衝突がなく、計器・音が車両状態と連動する。

## P4: 正式車両モデル

- ことでんバスの現代車両について写真、外形寸法、運転席資料の網羅性を調査。
- 対象個体1086号の実車仕様を記録し、推測と区別。
- 無料素材の利用許諾を確認、足りない車体・運転席部品はBlenderで制作。
- アニメーション、LOD、ミラー、衝突形状、ポリゴン/テクスチャの最適化。

**完了条件:** 外観より運転席の精度を重視したモデルが動き、720pで実測値が記録されている。

## P5: 高松市・御厩線

- PLATEAU＋OpenStreetMap等の利用規約・データ範囲を確認。
- 高松駅→県立総合プールの公式停留所順・経路・ダイヤを照合。
- 道路中心線だけでなく、車幅・車線・曲がる角・停止位置・信号を検証。
- 高松駅周辺からモデルを段階的に構築し、ストリーミングで全線へ延長。

**完了条件:** 実在路線をバスで通し運転でき、停留所と道路の差異が検証記録に残る。

## P6: 日本の路線バスの運行業務

- バス停停車、ドア、乗客の乗降、降車ボタン。
- 車内放送、行先表示、運賃・整理券、ダイヤ、遅延管理。
- 交通AIなどを必要に応じて拡張。

**完了条件:** 走行に加え、御厩線の1便を運行シミュレーションできる。

## Codexに対する作業単位

各作業では、以下を必須にする。

1. 対象マイルストーンと必要な変更ファイルを宣言。
2. 作業を最小の差分に分割。
3. 使用するUE APIとバージョン、必要プラグインを明記。
4. 実装、テスト、ドキュメントの更新。
5. ビルド/UEエディターでの実機試験ができない場合は、明確に `未検証` と記す。
6. マージ前に変更内容、確認方法、既知の問題をまとめる。
